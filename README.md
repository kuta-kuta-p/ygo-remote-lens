# 遊戯王リモート対戦 カード認識サブツール（仮称: YGO-Remote-Lens）

## 1. プロジェクト概要・背景
### 解決したい課題
- 実際の紙のカードを使った遊戯王のリモート対戦（Discord等でのWebカメラ対戦）において、**相手の盤面にあるカードのテキストや詳細がその場で分からない**。
- 遊戯王は1枚あたりの効果テキストが非常に長く複雑だが、カメラ越しの映像では文字が潰れて読めない。
- 毎回相手に「そのカード何ですか？効果は何ですか？」と聞いたり、自分でスマホ等でカード名を検索するのは手間がかかり、対戦のテンポが落ちてしまう。

### コンセプト
- MTG（マジック：ザ・ギャザリング）の公式リモート対戦ツール「SpellTable」にあるカード認識機能を、遊戯王向けに実現する。
- **個人開発で小さく早く作れる「オーバーレイ / サブツール型」**として構築する。
  - 通話自体は既存のツール（Discord等）をそのまま利用。
  - 相手のカメラ映像（画面キャプチャ、またはウィンドウ指定）からカードを認識し、画面の端に**「認識したカードの高画質画像・カード名・日本語効果テキスト」**を大きく表示する。

## 2. システム構成・利用スタイル（Webアプリ＋Pythonバックエンド型）

個人開発での作りやすさと、友達と遊ぶときの導入ハードルの低さ（インストール不要・URLを開くだけ）を両立するため、**「ブラウザベースのWebアプリ（フロントエンド）＋ Python（画像認識バックエンド）」**の構成を採用する。

### アーキテクチャ概要
- **フロントエンド（Webブラウザ / HTML・JS）**
  - ブラウザ標準の画面共有API (`getDisplayMedia`) でDiscord等の通話ウィンドウをキャプチャ表示。
  - キャプチャ映像上のカードのクリック（またはドラッグ範囲選択）を受付。
  - 画面右側のサイドパネルに、認識結果（高画質カード画像・日本語カード名・効果テキスト・認識履歴）を見やすく表示。
- **バックエンド（Python / FastAPI等）**
  - フロントエンドから切り抜かれたカード画像を受け取り、画像認識（ベクトル検索 / ハッシュ照合）でカードを特定。
  - カードIDに紐づく日本語テキスト・ステータス情報を返却。
- **友達と遊ぶときの共有方法**
  - まずは自分のPC（ローカル）で動かして自分用の補助ツールとして使用可能。
  - 友達にも使ってもらう場合は、`Cloudflare Tunnel` や `ngrok` 等でローカルサーバーの一時URLを発行して送るだけで、友達はブラウザでURLを開くだけで利用できる。

### 基本フロー（ステップ1：クリック/範囲指定型）
1. Discord等で相手とビデオ通話を開始する。
2. ブラウザで本ツールを開き、「画面キャプチャ開始」からDiscordのウィンドウを選択する。
3. 画面上の「相手の盤面にある気になるカード」をマウスでクリック（または四角くドラッグして囲む）。
4. ツールがその部分の画像を切り抜いてバックエンドに送信し、どのカードかを即座に判定（上下逆さま・180度回転も自動考慮）。
5. 画面右側のサイドパネルに、カード名・日本語テキスト・ステータスを大きく表示し、履歴リストにログとして残す。

### 発展フロー（ステップ2：自動検出・トラッキング型）
1. フィールド上に新しくカードが置かれたことをカメラ映像の差分や物体検出（YOLO等）で自動検知。
2. 自動的に認識して画面端に「今プレイされたカード」としてポップアップ表示する。

## 3. 技術調査・実現アプローチ

このシステムは大きく分けて **①画面取得**、**②カードの切り抜き（検出）**、**③カードの特定（画像検索）**、**④カード情報の表示（DB参照）** の4ステップで構成できます。

### ① 画面・映像の取得
- **Webブラウザアプリとして作る場合（超手軽・おすすめ）**
  - ブラウザ標準の `navigator.mediaDevices.getDisplayMedia()`（画面共有API）を使用。
  - インストール不要で、Discordのウィンドウを選択するだけでブラウザ内に相手画面を取り込める。
- **デスクトップアプリ（Python / Electron / Tauri）として作る場合**
  - Pythonなら `mss` や `OpenCV` + `PyQt / Flet / Tkinter` などで透過オーバーレイウィンドウを作成可能。

### ② カード領域の切り抜き・歪み補正
- Webカメラ映像ではカードが斜めになっていたり、逆さま（相手視点）になっていることが多い。
- **対策：**
  - クリックした周辺の四角形（カードの輪郭）をOpenCV等で検出して台形補正（透視変換）を行う。
  - または、最初はシンプルに「クリックした位置を中心に一定サイズを切り抜く（あるいはドラッグで囲む）」だけでも十分機能する。
  - 相手側のカードは上下逆さま（180度回転）で映ることが多いため、**「そのままの向き」と「180度回転した向き」の両方で照合する**のがコツ。

### ③ カードの特定（画像認識アルゴリズム）
1万枚以上の遊戯王カードから一瞬で特定するための手法。実はカードの文字を読む（OCR）より、**「イラスト部分の画像特徴」で検索する方がカメラの低画質に強く、圧倒的に精度が出ます**。

| 手法 | 仕組み | メリット | デメリット・注意点 |
| :--- | :--- | :--- | :--- |
| **1. 知覚ハッシュ (pHash / dHash)** | イラスト画像を縮小・白黒化して64bit等のハッシュ値にし、ハミング距離で比較 | 超高速・超軽量。Pythonなら `imagehash` ライブラリ等で数行で書ける。 | カードが斜めに歪んでいたり、切り抜き位置がズレると精度が落ちる（正確な切り抜きが必要）。 |
| **2. 特徴点マッチング (ORB / AKAZE)** | イラスト内の角や模様の特徴点を抽出して比較 | 回転や多少の傾き・サイズ変化に強い。 | 1万枚すべてと毎回比較すると遅いため、工夫が必要。 |
| **3. 画像埋め込みベクトル検索 (CLIP / MobileNet + FAISS)** ⭐️本命 | 軽量な画像AIモデルで画像をベクトル化し、類似ベクトルを高速検索 | **照明の反射・傾き・多少のズレ・低画質に非常に強い。** 数ミリ秒で1万枚から検索可能。 | 事前に対象カードのベクトルDB（数MB〜数十MB程度）を作っておく必要がある。 |

### ④ カードデータベース（画像＆日本語テキスト）の取得
- **YGOPRODeck API** (`https://db.ygoprodeck.com/api/v7/cardinfo.php`)
  - 全遊戯王カードの高画質イラスト画像（カード全体、およびイラストのみ切り抜き画像 `image_url_cropped`）が取得可能。
  - **ポイント：** `image_url_cropped`（イラスト部分だけの正方形画像）が公式APIで提供されているため、イラスト照合用のデータベース構築が極めて簡単！
- **日本語テキストの取得**
  - YGOPRODeckは英語ベースだが、カードの固有ID（パスコード / 8桁の数字）が共通している。
  - オープンソースの遊戯王カードデータ（`yugioh-card-history` や YGOPro系の日本語CDB/JSONデータ）とIDで紐付けることで、正確な日本語カード名・効果テキスト・ルビを取得できる。

## 4. おすすめの開発ステップ（ロードマップ）

いきなり全部を作らず、以下の順番で少しずつ動かすのがおすすめです。

- [ ] **Step 1: カード認識エンジンのPoC（概念実証）作成**
  - まずは一部のカード（例：有名なカード100〜1000枚、または全カード）のイラストデータを取得。
  - スマホで撮った斜めのカード写真や、Webカメラ越しの画像を1枚入力したら、「これは『ブラック・マジシャン』です」と当てられるPythonスクリプトを作る。
- [ ] **Step 2: 画面キャプチャ＋クリック認識UIの作成**
  - Discord等の画面を取り込み、マウスで囲んだ（またはクリックした）場所のカードをStep 1のエンジンに投げて、画面の横にカード情報と日本語テキストを出す。
- [ ] **Step 3: 対戦向けの便利機能追加**
  - 認識したカードの履歴リスト（相手が墓地に送ったカードや発動したカードを後から見返せる）。
  - 180度回転（相手の向き）への自動対応。
  - カードが置かれた位置の自動検出（クリック不要化）。
